一、已经接入的玩法

1. 按 1 沿路行军，按 2 自由行军。
2. 按 3 只进入查看与管理；重复按 3 无额外作用，不再循环范围圈。
3. 模式 3 点击军队，右侧显示信息；原先确认的移动命令继续执行。
4. 进入自身攻击范围和观察范围的敌军会自动交战，不自动追到视野内的敌军身边。
5. 交战单位停止移动，不能继续提交移动路线。
6. 模式 3 选中己方交战军队，右侧“逃跑”解除移动锁定。
7. 逃跑一次扣除当前剩余人数的 10%，重复点击不会重复扣除。
8. 逃跑有可配置的保护时间，默认 5 秒：期间不能开火，也不会被重新锁定，但敌军仍能造成伤害。
   保护结束后仍在敌方射程内，可以再次进入交战。
9. 人数百分比用作部队耐久，不显示具体伤害数字，不添加开火特效。
10. 伤害同时结算，单位在数组里的先后顺序不赋予先手优势。

二、战力与人数

ArmyCombatDefinition 配置满编基础攻击、防御、观察范围、攻击范围和建制。
不同建制、兵种的基础战力由各自资产数值决定，不在程序中写死强弱关系。

人数战力倍率：
75%～100%：100% 战力。
50%（含）～75%（不含）：75% 战力。
25%（含）～50%（不含）：50% 战力。
大于 0% 且小于 25%：25% 战力。
0%：部队被消灭。

本版基础公式：
每秒人数损失 = 攻击方满编攻击 × 攻击方人数倍率 × 100 / (100 + 防御方防御)。
再乘本次模拟步长，得到本次伤害。
人数内部使用小数累计，界面显示整数或百分比，避免小伤害被整数截断。
该公式只是可调的确定性原型，不代表伤害平衡已经完成。

满编人数默认：班 7 人，相邻建制 3:1。
团 567，旅 1701；比例与班人数均可在资产中修改。
原始移动速度仍来自 ArmyDefinition，战斗参数来自独立 ArmyCombatDefinition。
目前人员损失影响攻击发挥，不自动降低移动速度。

三、玩家视角与敌军情报

右上“切换玩家”在 A/B 间切换查看和操作权限。
这只是本地视角切换，世界时间继续推进，不是回合结束或轮流下令系统。
切换会清理旧选择和未提交路线，避免带着上一玩家的私人信息操作。
模式 1/2 只能选择当前玩家的军队下达命令。

敌军超出我方所有在地图上部队的观察范围：隐藏实时棋子，不显示实时位置。
敌军进入视野但没有交战识别：显示未知棋子和问号。
有效交战后：交战双方分别记录对方单位类型。
敌军逃出视野：位置隐藏，但识别记录保留。
再次发现且没有进入过恢复据点：恢复已识别棋子。
进入恢复据点并完成入点过渡：清除所有玩家对该单位的识别记录。
出点后重新被发现：先显示未知棋子，重新交战后再识别。

模式 3 显示已知军队的人数百分比，包括当前可见且已识别的敌军。
敌方右侧只允许查看公开的类型、建制、百分比，不能查看我方内部参数、路线或恢复信息。
驻点部队不提供地图观察视野，不参与地图攻击。
当前没有“最后已知位置”标记、地形遮挡或森林隐藏判定。

Fog Enabled 关闭时，所有地图单位可见，敌方控制区域红色显示。
Reveal Types Without Fog 默认关闭：无迷雾并不自动识别所有敌军类型。
如用于调试，可开启它，使无迷雾时直接看到真实单位类型。

四、城市地形与占领/恢复据点

底图上的城市街区仍是普通的道路和地形区域，可移动、交战。
单纯经过城市街区，不隐藏军队、不刷新情报、不恢复人数。
RecoveryPoint 是单独的占领/恢复点，不是能开火的防守建筑。

入点操作：
1. 军队靠近己方恢复点，未处于交战状态。
2. 按 3，点击军队，右侧“进入恢复点”。
3. 完成入点时间后，棋子从地图隐藏。
4. 己方据点名字旁显示内部部队小图标，点击图标可选择该部队。
5. 也可点击据点，在右侧内部部队列表选择。
6. 选择内部部队后，右侧“开始恢复”“取消恢复”“出点”管理。

入点、出点默认各 2 秒，可配置。
入点过程中部队仍在地图上，可以被攻击；受到交战会中断入点。
出点过程中仍在据点内部，不能攻击或防守；过渡完成后回到地图。
逃跑中的军队可以在满足安全条件时入点；交战中的不允许直接入点绕过逃跑。
己方据点附近有敌军时，不允许开始入点。
默认收纳上限 3 支部队，可配置，内部部队不计入外围防守人数和地图区域比较。

恢复按时间增加人数，消耗该据点的资源库存。
默认每秒恢复满编人数的 2%，每恢复 1 人消耗 1 资源，可分别配置。
恢复完成或物资不足时结束恢复，留在点内。
取消恢复保留已经恢复的部分，也不会自动出点。

据点占领：
只有地图上的军队参与占领判断。
当前所有者在占领范围内还有军队时，敌方不能推进占领。
没有守军且进入范围的军队有唯一人数最多的一方时，持续占领默认 8 秒。
平局、无人或守军回来会清空当前占领进度。
易主时，未撤出的原所有者驻点部队被消灭，不作为防守火力。
本版采用“消灭”，没有单独的俘虏库存或交换系统。

五、固定像素格与持续控制

TerritoryControlSystem 用隐藏格子计算归属，不把移动变成格子移动。
Use Pixel Cell Size 开启时，Cell Pixels 控制底图原始像素格大小。
本图默认 Map Pixels = 1995×1348，Cell Pixels = 128×128。
格子转换为固定世界坐标，缩放不改变格子大小。

初始中立格：实际地图军队人数唯一最多的一方取得控制。
已经控制的格：无人时保留；平局时保留；其他玩家人数严格更多时更换控制。
没有相邻四格传播，也不自动向空地染色。
有已归属恢复点的格优先采用据点所有者。
同格存在不同所有者的多个恢复点时判为中立；制作地图时建议避免这种布局。
驻点内部军队不参与区域人数比较。

模式 3 默认显示控制覆盖：我方绿色；迷雾下其他区域不覆盖。
无迷雾时敌方区域红色。
Only In Inspection Mode 可关闭，让覆盖在模式 1/2 也显示。
下方公开敌方据点数和占领区域百分比，符合当前策划的情报例外。
百分比按地图 Bounds 面积计算，包含未控制区域和水域；尚未增加可占领陆地面积过滤。

六、当前测试场景

原来的 3 支军队作为玩家 A：2 支步兵团、1 支装甲团。
另加入玩家 B 的 1 支步兵团、1 支装甲团，用于测试接敌和视角。
A 第一支步兵团初始人数 70%，靠近西部恢复点，便于测试恢复。
西部恢复点属于 A，东部恢复点属于 B，南部恢复点中立。
地图没有被重画，新增的是场景军队、据点和系统引用。

快速测试：
1. Play，按 3，点击 A 的第一支步兵团，尝试进入恢复点和恢复。
2. 点击据点旁的军队小图标，取消恢复或出点。
3. 按 1/2 将另一支 A 步兵团靠近前方未知敌军，进入射程自动交战。
4. 按 3，选择交战军队，点击逃跑；再按 1/2 绘制撤离路线。
5. 点击“切换玩家”，验证 B 的信息和控制权限。

七、新增脚本与挂载

ArmyCombatDefinition.cs
  数据资产；Project → Create → Campaign Demo → Army Combat Type。
  每个兵种/建制可建立自己的资产，配置基础战力和射程。
  CombatMath 是同文件里的纯计算工具，不挂物体。

BattleUnit.cs
  每支军队挂一个，填写唯一 Unit Id、Owner Id、Combat Definition、初始百分比。
  当前人数和状态是每个军队自己的运行数据，不共享到类型资产。
  保留原 ArmyRoadMover、ArmyFreeMarchMover 和 SpriteRenderer。
  新军队必须同时加入 RoadMarchSceneSetup.Scene Armies 和 BattleWorld.Units，不能只登记一份。

BattleUnitView.cs
  根据当前玩家显示真实、未知或隐藏棋子。
  BattleWorld 运行时自动补齐，不通过关闭整个军队 GameObject 实现隐藏。

RecoveryPoint.cs
  占领/恢复据点物体挂一个，配置 ID、名字、主人、范围、占领时间、入出点时间、库存、恢复速度等。
  需要在 BattleWorld.Points 数组登记。
  Exit Offset 是出点位置偏移；制图时请保证出点位置在合法地面，不落在水中。

PlayerIntelStore.cs
  普通 C# 情报记录，不挂物体；由 BattleWorld 持有。

BattleWorld.cs
  挂 GameRoot，绑定原 RoadMarchSceneSetup、全部 BattleUnit 和 RecoveryPoint。
  Players 数组登记 A/B/C 等所有玩家；单位 Owner Id 必须属于该数组。
  可设置迷雾、逃跑损失比例、保护时间、模拟步长和统计人数上限。
  单位和点都必须登记，当前没有运行时生产新单位自动注册的流程。

TerritoryControlSystem.cs
  挂 GameRoot，World 指向 BattleWorld，Bounds 与地图世界范围一致。
  设置固定像素格、覆盖颜色和显示模式。
  BattleWorld.Territory 指向该组件。

BattleHUD.cs
  挂现有 Command UI 的 Canvas，World 指向 BattleWorld。
  运行时创建右侧详情、底部统计、玩家切换按钮、百分比和据点收纳图标。
  中文字体目前使用系统 Microsoft YaHei/SimHei，Font 字段也可直接绑定自己的字体资产。

BattleSceneInstaller.cs（Editor）
  显式配置本次测试军队、据点和系统引用，不修改底图或道路。
  会重设其负责的测试数据；你手动修改场景后不要重复执行来启动游戏。

BattleVerification.cs（Editor）
  自动化验证与预览工具，不挂物体。部分验证入口结束后会退出 Unity 编辑器。

修改的旧脚本：
MouseModeStateMachine：3 改为固定管理模式。
ArmyRouteMotor：增加交战移动锁、停止命令和路线显示权限。
ArmySelection：过滤敌方与驻点单位，支持清理选择。
RoadMarchController / FreeMarchController：禁止交战中规划移动，交战发生时取消未提交草稿。

八、数值从哪里改

战斗资产：Assets/Game/Data/Combat/InfantryRegiment.asset、ArmorRegiment.asset。
Full Strength Attack：满编攻击，最终换算为每秒人数损失。
Defense：防御。
Vision Radius：观察半径。
Attack Radius：攻击半径，通常应小于观察半径。
Echelon / Squad Size / Echelon Ratio：建制容量。

军队实例的 Starting Personnel Percent：初始完整程度。
据点的 Repair Fraction Per Second：每秒恢复满编人数的比例，0.02 等于 2%。
Resource Per Person：每恢复 1 人消耗多少资源。
BattleWorld.Escape Loss Fraction：0.1 等于当前人数损失 10%。
Escape Grace Seconds：允许撤离的保护时间。

建制容量建议停止 Play 后修改。
目前参数是功能测试值，没有承诺平衡性。相邻建制基础战力需要你建立不同资产调整。
Personnel Limit / 编制上限目前用于统计展示；由于还没有生产系统，不存在招募时的上限拦截流程。
